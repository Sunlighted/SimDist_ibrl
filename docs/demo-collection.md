## 35. stage-2 base policy 的什么属性决定 adapt？——成功率无关，采集口径的接触相步数有信号（2026-08-01/02）

### 起因
`dynens_adapt` 系列里，用 50 条 target demo 训的 base（policy_only **0.59**）adapt 到
**0.770**，而用 20 条训的（policy_only **0.39**）adapt 到 **0.952**。"更强的 base 反而更差"。

### ★ 核心工具：policy/dynamics 可以逐位干净地交叉互换
stage-2 只训 `model.policy`、stage-3 只训 `model.dynamics`，所以同一 stage-1 出来的
所有 adapt run 之间 **encoder / value / value_target / reward / decoder 逐位相同**
（实测 max|Δ| = **0.00e+00**），只有两组张量不同。⇒ 4×4 析因表可直接做。

| MPPI(100局) | D=σ.02-n20 | D=σ.1-n20 | D=σ.1-n50 | D=σ.1-n500 | 行均值 |
|---|---:|---:|---:|---:|---:|
| P=σ0.02-n20 | **0.980**◆ | 0.870 | 0.890 | 0.840 | 0.895 |
| P=σ0.1-n20 | 0.850 | 0.850◆ | 0.750 | 0.740 | 0.798 |
| P=σ0.1-n50 | 0.800 | 0.790 | 0.870◆ | 0.700 | 0.790 |
| P=σ0.1-n500 | 0.860 | 0.910 | **0.960** | 0.900◆ | **0.907** |
| P=nobc | 0.850 | — | 0.740 | — | 0.795 |
| 列均值 | 0.868 | 0.855 | 0.842 | **0.795** | |

方差分解：**policy 53% / dynamics 17% / 交互 30%**；对角线均值 0.900 vs 非对角 0.830
（共适应 **+0.070**）。⚠️ 交叉组合不是可部署配置（用户规则），交叉表的价值是**量化验证
共适应**，不是给配方。**最干净的一列**：固定 D=σ.02，四个非共适应 policy 的
policy_only 跨 **0.11→0.83（7.5×）**，MPPI 全在 **0.80–0.86**（彼此 1σ 内）；唯一跳出来的
是与该 dynamics 共同适配的那个（0.980，比另三格均值高 0.113，z≈4.7）。
另：**D=σ.1-n500 是最差列**（0.795，比最好低 0.073）——强+窄 base 压窄采集覆盖（§31 已记）。

### ⭐ 主结论：能预测 adapt 的只有「MPPI 采集口径的接触相步数」
9 个 base（adapt 已知）上测了 **17+ 个候选指标**，只有一个有信号：

| 指标 | ρ (n=9) | **ρ (n=10, 含盲测)** | p |
|---|---:|---:|---:|
| **`contact_steps`（MPPI 采集口径）** | +0.800 | **+0.855** (R²=0.78) | **0.0016** |
| demo 级 contact_frac | +0.731 | 0.040 (n=8) |
| round-0 MPPI 分 | −0.356 | 0.35 |
| **`policy_only`（成功率）** | **+0.201** | **0.60** |

**全部被证伪的**：成功率、stage-2 BC loss、held-out MSE、`val_deploy`（σ0.1 留出集）、
demo 覆盖密度、Jacobian `‖∂a/∂s‖`、`a_disp`（是否坍缩成常数动作）、想象 rollout 自洽性
`roll_drift`、policy-only rollout 的 contact_steps/contact_cov/reach_frac/jerk、
`cov_all`/`cov_contact`/`novel_frac`/`base_elite`。

**关键区分**：同一个量在 **policy-only rollout** 上测是 ρ=+0.26 且方向相反，在 **MPPI 采集**
上测才是 ρ=+0.80。stage-3 采集用 MPPI（policy 只供 100/350 个候选），所以"policy 诱导什么
数据"**必须在闭环里测**。σ0.02_new 是最锋利的例子：demo 级 contact_frac 0.207（高档），
MPPI 采集口径 **56.0（全场最低）**，adapt 0.62 —— demo 统计量骗人，采集口径没骗。
机制与 §27 一致：天花板由**插入相**模型误差定 ⇒ 适配器需要插入相样本。
**一个预注册成功**：跑 adapt 前基于 demo 级 contact_frac 最低（0.133）预测 σ0.1_new 会更差
（与"它数据最干净"的直觉相反），实测 0.46–0.58 vs 对照 0.87–0.91，方向+量级都对。
**★ 通过了一次外插盲测（2026-08-02）**：`threading_d0_target_sig01expert_at002`
（σ0.1 专家在 σ=0.02 下采集）的 base 测得 `contact_steps=**23.0**`（比已有最低的 56.0 还低
59%，在已有范围 [56,148] 之**外**）。在**只看这个数、完全不知其 adapt** 的情况下预注册：
秩 = 排最后(<0.460)、点估计 0.428（线性外插）、95% 区间 [0.113,0.743]。
实测 50-75k = **0.353±0.010（25 个 eval 点）** ⇒ **秩预测成立**，点估计偏高 0.075。
⚠️ 保留：这是**相关+预测**不是因果（通过换数据集间接改变 contact_steps，未直接干预）；
其余三个新点测量时已知 adapt（非盲测）；单 seed。

### 挑 demo 有因果效应，但要配数量
`scripts/select_matched_demos.py`：按 eef-init `|r|` 分位**分层**（每层取 1 条 ⇒ 边缘分布
按构造复现，覆盖不被收窄）+ 层内挑 (len, contact_frac, |Δa|) 最接近目标 profile 的。
`--mode antimatch` 给同覆盖的最差质量对照臂。

| base（σ=0.1 同池） | eef-init | contact_frac | 50-100k |
|---|---:|---:|---:|
| matched n100 | 93.7mm | 0.191 | 0.907(30-50k) |
| matched n50 | 93.8mm | 0.200 | **0.925** |
| matched n20 | 92.4mm | 0.199 | 0.897 |
| prefix n20 | 77.8mm | 0.164 | 0.884 |
| prefix n50 | 89.4mm | 0.165 | **0.770** |

- **matched n50 − prefix n50 = +0.155 (z=22)**：同池、同专家、同 σ、同 strict，覆盖还更宽，
  **只换挑哪 50 条**。σ0.02 相对 prefix n50 的总落差 0.182 里 0.155 被"轨迹质量"解释掉。
- **n=20 上只值 +0.013 (z=2.1)**，n=100 与 n=50 持平（0.907 vs 0.909）⇒ **质量筛选要配
  数量才兑现，且 ~50 条饱和**。
- ⚠️ 早期窗口会骗人：25k 时 matched n20 看着"完全无效"，50-75k 反超（0.906 vs 0.876）。

### 我自己收的数据全塌到 0.35-0.72 —— 三个假说逐个被证伪
老池子派生的 base 是 0.77-0.95，我用现有专家新收的四批全在 **0.35-0.72**。逐个排查：

| 假说 | 判据 | 结果 |
|---|---|---|
| BC 欠训 | 收敛曲线 | ❌ 训练 loss 0.0020-0.0048，比老池还低 |
| 数据格式/字段 | 结构 diff | ❌ obs keys / `state`==STATE_KEYS 重建(1e-8) / 动作范围 / reward 全一致 |
| `save_masked_state` | 代码 | ❌ `hole_offset=0` 时直接 return |
| 渲染配置改物理 | 见下方 §27 修正 | ❌ 逐位相同 |
| **σ（窄 vs 宽初始化）** | σ0.02_new 与 σ0.1_new **都**塌 | ❌ |
| **`--max_demo_len 150` 砍长尾** | 放宽到 400 重收，60 条**无一超过 150 步**(最长 147) | ❌ 长尾本就不存在 |
| **专家在自己分布外 ⇒ 修正动作多 ⇒ 接触相长** | σ0.1 专家在 σ=0.02 采集，contact_frac **降到 0.119(最低)** | ❌ 方向相反 |

**浮现的替代读法（未验证）**：demo 级 contact_frac 主要由「**用哪个专家**」决定，与 σ、与
分布内外都无关 —— `newtgt` 系一律 0.16-0.21，`rlprior_sig01` 系一律 0.06-0.14。两者最大的
结构差别是 IBRL 里挂的 **prior 类型**：flow BC prior（MimicGen source demo 训的，动作平缓）
vs RL snapshot prior（`sgft_source_agent`，快而利落）。可用现有资产测（换 prior 重收一批）。

### ⚠️⚠️ 两个 provenance 陷阱（作废了一批解读）
**① `TopkSaver` 会覆盖 `model0.pt`，用它收的数据事后不可考。**
`threading_d0_target_dynamics`（σ0.02 原始 20 条，adapt 0.952）的 sidecar 记
`source_weight=threading_ibrl_newtgt_seed1/model0.pt`，但：数据集写于 05-28 **04:29**，
`model0.pt` 写于 **13:20**，训练到 14:22 才结束。把 `train.log` 的 `Time spent` 累加
映射到时钟：**收集用的是 step 220000（总 400k 的 55%，eval 0.98，未饱和）的 ckpt**，
之后又被 250k/300k/**380k**(1.00) 覆盖了 3 次。
**判据 = `scripts/diag_demo_provenance.py`**（把记录的 state 喂回专家，比 `eval_mode=True`
下的确定性动作）：原始集合 **0.0% 逐位吻合、中位误差 0.22**；阳性对照（我新收的、确定出自
当前 ckpt）**中位误差 0.000、吻合 73–81%**。⇒ **那 0.952 不能归因于 σ**，收集策略是不可
恢复的混淆变量。**以后收集必须把 ckpt 快照进数据目录、或至少把 sha256 写进 sidecar**
（新数据集已加 `expert_provenance` 字段）。
**② 现有 σ0.1 池全部由 σ0.02 训练的专家收集。** `threading_d0_target_expert_n500`
的收集专家是 `newtgt`（`train_hand_init_perturb_joint_sigma: None` = 0.02），却在 σ=0.1 下
采集 ⇒ **专家在自己初始分布之外**。所有 prefix/matched 臂都建立在这个未受控变量上。
用 σ=0.1 上训练的 `threading_ibrl_rlprior_prior_sig01_seed1` 重收（`threading_d0_target_sig01new`）。

### ✅ 修正 §27：`state_only_no_render` 改变物理 —— 没有复现
同 seed `reset()`、同开环动作序列、40 步后，三种配置（`cams=[] render=T` /
`cams=[eih] render=T` / `state_only_no_render=T`）**逐位相同（max|Δ|=0.00e+00）**。
当年那个观察极可能与我第一版探针犯了同一个错：**用 `set_state_from_flattened` 恢复了
sim_state，但 OSC 控制器的内部 goal 是 `reset()` 时按当时机器人位姿初始化的、不在 sim_state
里** ⇒ 三个 env 把第一个动作解释在不同参考系下（我的 v1 探针因此测出 step1 差 1.5e-2、
终端差 1.8）。**凡是"恢复 sim_state 后继续 step"的实验都要注意这个 confound。**

## 37. 为什么"原始那 20 条"复现不出来 —— 抽样方差 + source 覆盖（2026-08-02/04）

> ⚠️⚠️ **本节的两个核心结论已被 §38 推翻，读前必看 §38。**
> ① 「原始的 0.932 在 3.7σ 之外，抽样运气解释不了」—— **错**。当时的抽签方差是在**一个**池上
> 测的，且 0.932 本身是单次抽样；§38 用 4 组多 seed（n=19）重测抽签 std=**0.092**，并证明
> 我在 §38 中"复现 ORIG"的那个 0.937 只是同一 setting 五次抽样（0.743–0.937，均值 0.826）
> 里的最高值 ⇒ **ORIG 的 0.933 与它并无差别，两者都是单抽签。**
> ② 「`cover_lat%` 是唯一能分离原始的量（+5.33σ）」—— **被证伪**：§38 的采集噪声实验把
> `cover_lat%` 降了 3.6–6.8 点，adapt 反而涨 ⇒ 它是相关不是因果。
> 本节其余内容（工具、provenance 陷阱、`state_only_no_render` 的修正）仍然有效。

### 起因
`threading_d0_target_dynamics`（20 条 σ0.02 demo）的 SimDist adapt 是 **0.932/0.926/0.950**
（3 个 replicate），而**任何**其他 20 条集合都到不了。§35 已查明它的收集 ckpt 已被
`TopkSaver` 覆盖（step 220k/400k，未饱和）。本节尝试复现并追因。

### ★ 关键基础设施结论：stage-2 BC 完全确定 ⇒ adapt 噪声只有 ±0.027
三个 replicate 用同一批 demo + 同 seed，其 **policy 头逐位相同**（`max|Δ|=0.000e+00`，
`scripts/diag_replicate_policy_spread.py`）⇒ 它们 adapt 的 0.926-0.950 **全部来自 stage-3
采集/eval 的随机性**。所以"同一 base 的 adapt 噪声 = ±0.027"，这是本节所有比较的标尺。

### ① 20 条这个规模本身有 ±0.098 的抽样方差（大 3.6 倍）
从**同一个 500 条池子**（`threading_d0_repro952_pool500`，同网络 220k 快照、同一次采集）
抽 5 组**互不相交**的随机 20 条（`scripts/make_random_subsets.py`），25-50k 窗口：

| g2 | g3 | g0 | g1 | g4 | std / 极差 |
|---:|---:|---:|---:|---:|---:|
| 0.455 | 0.517 | 0.584 | 0.578 | 0.746 | **0.097 / 0.29** |

⇒ **"哪 20 条"是个高方差随机量**，这解释了 §35 里一大批"无法归因"的臂间差异（0.63/0.68/0.71
基本都落在这条带里）。但**原始的 0.932 在 3.7σ 之外**，比最好的随机组还高 0.19 ⇒ 抽样运气
解释不了它。

### ② ⭐ 唯一能把原始分离出来的量：与 **source 蒸馏分布**的 latent 覆盖率
用户假说（2026-08-04）：stage-1 的 encoder/dynamics 是在 `source_diverse_v2`（10 万条 SOURCE
轨迹、80 万步）上蒸馏的，dynamics 的先验精度在**那个**分布上最高；target demo 落在其内/外，
stage-3 面对的是"小幅修正已建模区域"还是"学新区域"，是两回事。
`scripts/diag_demo_vs_source_coverage.py` 在 **20 个** demo 集上测（原始状态 + **冻结 latent**
两个空间，均以 source 自身的最近邻尺度为标尺）：

| 量 | 原始 | 其余 19 个 | z | 排名 |
|---|---:|---:|---:|---:|
| `d_src`（到 source 最近邻距离） | 0.675 | 0.861±0.131 | −1.42σ | **1/20** |
| `cover%` | 52.7 | 28.2±9.7 | +2.53σ | **1/20** |
| `d_src_lat`（latent） | 10.786 | 12.978±0.781 | −2.81σ | **1/20** |
| **`cover_lat%`** | **67.4** | **32.6±6.5** | **+5.33σ** | **1/20** |

**这是 ~15 个测量里第一个把原始从群体中分离出来的量**（此前全部把它放在群体内部：
长度分布含 std / contact_frac / |Δa| / 逐维动作 / 饱和率 / 夹爪 / 抓取几何 / 集合级有效维度 /
轨迹间距离 / BC loss / latent aliasing / 局部动作多样性 / policy-only 行为 / bc_steps / bc_lr）。
**符号方向 = 越靠近 source 蒸馏分布越好**（落在"小幅修正更容易"一侧）。
⚠️ 但其余 19 个之间相关性弱（`cover_lat%` ρ=+0.381 p=0.097；去掉原始后 +0.278），且
`cover_lat%` 与 demo 长度混淆（ρ=+0.696）—— source 是 45%-成功的混合分布、含大量慢轨迹，
所以长 demo 天然"像 source"。

### ③ 三臂干预：**分层是必要条件；贪心挑单标量有害**
`scripts/select_by_source_coverage.py`，从同一个 500 池选 20 条（同网络/同采集/同超参，
**只换挑选准则**），对照是上面那 5 组随机：

| 臂 | 长度分层 | 挑覆盖率 | cover_lat% | len std | 1-10k | 10-25k | **25-50k** |
|---|---|---|---:|---:|---:|---:|---:|
| 原始（丢失 ckpt） | — | — | 67.4 | 14.4 | 0.837 | 0.913 | **0.932** |
| **`lenmatch`** | ✓ | ✓层内取最高 | 65.2 | 13.3 | **0.711** | **0.740** | **0.805** |
| `pure` | ✗ | ✓贪心 top-20 | **71.7** | **10.6** | 0.401 | 0.502 | 0.580 |
| `lenrand` | ✓ | ✗层内随机 | 36.1 | 16.1 | 跑中 | — | — |
| 5 组随机 | ✗ | ✗ | 32.6 | ~14.7 | 0.442±.034 | 0.524±.079 | 0.576±.097 |

- **`lenmatch` 三个窗口全部超出随机带**（1-10k 高 7.9σ、25-50k 高 2.4σ，且高于最好的随机组
  0.746）⇒ **第一个成功的选择干预：同池 20 条从 0.576 推到 0.805（+0.23）**，与原始的差距
  从 0.36 缩到 0.13。
- **`pure` 覆盖率最高（71.7）却落在带内（0.580）** ⇒ **光有高覆盖率不够**。它的失败机制清楚：
  贪心 top-k 把长度 std 从池子的 14.7 压到 10.6，**多样性被挑没了**。
  ⚠️ 这与 §35 的 `select_matched_demos.py` 之所以用**分层**而非贪心是同一个理由 —— 起 `pure`
  臂时又踩了一次。**教训：本 pipeline 里任何"按单个标量贪心挑 demo"的做法都必须加分层约束。**
**★ `lenrand` 出来了 ⇒ 这是一个纯交互效应，两个主效应都是 0**（严格同窗口 = 三臂都有数据的
前 32 个 eval 点）：

| | 挑覆盖率 ✗ | 挑覆盖率 ✓ |
|---|---:|---:|
| **不分层** | 0.495（5 组随机） | **0.479**（`pure`, cov 71.7） |
| **分层** | **0.432**（`lenrand`, cov 36.1） | **0.723**（`lenmatch`, cov 65.2） |

覆盖率单独 = **−0.016**；分层单独 = **−0.063**；两者同时 = **+0.23**。
交互项 = 0.723−0.479−0.432+0.495 = **+0.307**，**全部效应都在交互项里**。
（同窗口参照：原始 0.871、随机带 0.495±0.062。）

⇒ **判词：用户假说成立，但形式更强 —— "深在 source 蒸馏分布内"是有效变量，但必须在保住
多样性（长度分层）的前提下才兑现。单独拉高 source 覆盖率完全无效**（`pure` 的 71.7% 甚至超过
原始的 67.4%，成绩却等于随机）。机制：贪心 top-k 同时拿到"高覆盖"和"低多样性"（len std
14.7→10.6），两者相抵；分层强制每个长度区间各取一条，等于**在多样性约束下最大化覆盖率**。
这也为 §35 里 `select_matched_demos.py` 用分层而非贪心提供了因果依据（此前只是防御性设计）。
**可操作准则：在保多样性的分层约束下最大化与 stage-1 蒸馏分布的 latent 覆盖率** —— 把同池
20 条从 0.495 推到 0.723，与原始的差距从 0.376 缩到 0.148。

### ④ stage-2 BC 的超参一直是次优的（`bc_steps` / `bc_lr` 从未扫过）
`scripts/ablate_bc_steps.py`（增量训练 + 每个 checkpoint 跑 100 局 policy-only）：

| 数据集 | 现用 3e-4/1000步 | 各 lr 的最优 | 差 |
|---|---:|---|---:|
| 原始 (adapt 0.932) | 0.350 | **0.530**（lr 1e-3, 200 步） | +0.18 |
| snapB_160000 | 0.400 | 0.570（3e-4, 300 步） | +0.17 |
| snapB_400000 | 0.150 | 0.190（3e-4, 600 步） | +0.04 |

- **1000 步对所有小 demo 集都是过训**，最优在 ~300 步（~50 epoch）；`val` loss 从 150 步起
  就单调上升。**stage-2 完全没有正则**（Adam 无 weight decay、policy 头无 dropout），
  唯一的隐式正则就是"训多少步"。
- **更大的 lr 更好**（1e-3 @200 步 > 3e-4 @300 步 > 1e-4 @1200 步），方向是"大 lr + 少步数"。
- ⚠️ **`bc_steps` 固定 ⇒ epoch 数随 Σtrans 浮动 3 倍**（62-193），这在 §35 的 8 臂 snapshot
  实验里与"训练阶段"绑在一起变。但 `snapB_400000` 在**两个 lr × 6 个步数点**下峰值都只有
  0.18-0.19（另两个集合能到 0.47-0.57）⇒ **"饱和专家的数据对 BC 本质上更差"这个结论保住了**，
  不是超参没调好。
- ⚠️ **policy_only 不预测 adapt**（§35，ρ=+0.20），所以"更好的 BC 超参 ⇒ 更好的 adapt"**未经
  验证**，需要单独跑。
- 代码细节：`update_bc_policy` 的 Adam 是**懒构造**（`rl/simdist_agent.py:444`），lr 只在第一次
  调用时固定，后续传值被忽略 ⇒ 一个进程一个 lr。

### ⑤ demo 数据只经由 stage-2 BC 进入（代码审计）
`train_simdist_adapt.py` 里 `demo_replay` 只有三处：`bc_finetune`(289)、`dyn_demo_frac>0`(358-361,
本节全部 run `=0.0`)、`selfdistill`(369-386, `=0`)。⇒ **0.32 的 adapt 差距全部由那 1000 步 BC
产生的 policy 函数承载**，没有第二条路。
另：`load_demos_to_sequence_buffer:265-268` 因 obs 不存终端状态，每条 demo 的最后一个 transition
是**自环**（状态被复制）；但 BC 的 segment start 上限是 `T-H`、`update_bc_policy` 只用
`states[:, :H]`，所以它**永远进不了 BC**。

### ⑥ 流形外行为：20 条对 37 维状态空间的约束接近于零
`scripts/diag_offmanifold_divergence.py` / `diag_policy_behavior_divergence.py`：

| 状态集 | 跨网络分歧 | 同网络不同 demo | 同 demo 同 seed | 动作自身跨状态散布 |
|---|---:|---:|---:|---:|

| **流形外** | **0.73-0.75** | 0.56 | **0.0000** | 0.93-1.05 |

- 噪声地板 = **0** ⇒ 0.56-0.75 全部归因于 demo 差异。
- **流形外分歧达动作自身散布的 80%**，而 `novel_frac` 对所有 base 都是 **0.9986-1.0000**
  ⇒ **100% 的 stage-3 采集发生在流形外，而 demo 对那里几乎没有约束**。这解释了为什么十几个
  demo 内的统计量全部失效 —— 它们与决定成绩的东西之间隔着一个几乎自由的自由度。
- 闭环行为：从**同一初始状态**出发，第 5 步 eef 就差 35mm（**没有"前 20 步一致"**）；
  `P_repro` 的 rollout 游荡到自己 demo 尺度的 **64 倍**远（另两个是 6.9×/10.0×）。

## 38. ★ stage-2 demo 采集准则 —— 先量噪声地板，再谈效应（2026-08-05/07）

### 一句话
**单次 20 条 demo 采集的 adapt 方差 σ≈0.09-0.11，比今天测过的**任何**可控干预（≤0.19）都大。
在测出这个数之前做的 20 多个实验，绝大多数结论作废。唯一经预注册复现存活的是
**「用尚未触到自己天花板的策略采集」+0.14**。

### ① 抽签方差 = 0.092（四种独立方式测得，这是本节的标尺）
"同一个采集策略、同一脚本、同配置，只换随机种子"的 adapt 分布：

| 组 | 采集策略 | n | 均值 | 组内 std |
|---|---|---:|---:|---:|
| **A** | N3@160k σ=0.02（**未触顶**） | 5 | **0.826** | 0.076 |
| B | N3@400k σ=0.02（已触顶） | 5 | 0.687 | 0.106 |
| C | N1@380k σ=0.1（已触顶） | 4 | 0.645 | 0.112 |
| D | N2@220k σ=0.02（已触顶，池内随机 20 条） | 5 | 0.574 | 0.109 |

四组合并的**组内 std = 0.092 (n=19)**。⇒ **两次独立单抽样要相差 >0.26 才显著**（2√2×0.092）。

### ② 唯一存活的干预：采集策略"是否已触顶"
`N3 = threading_ibrl_newtgt_sig01_snap_seed1`（首次 eval=1.00 在 **240k**），
同网络/同 σ/同脚本/同 adapt cfg，唯一变量是采集 ckpt 的训练阶段：

- **预注册复现**（A vs B，各 5 seed）：**Δ=+0.139，SE=0.058，z=+2.39，22/25 配对胜出**
- A 的均值高于**全部三个**已触顶组（0.826 vs 0.687/0.645/0.574）；A vs 三组合并(n=14)
  **Δ=+0.191, z≈4.0**

⚠️ **事后估计被 winner's curse 抬高了 2.4 倍**：把 14 个**单次抽样**按同一判据分组时是
0.877 vs 0.540（Δ=**0.337**, z=5.63, 范围完全不重叠）；多 seed 复现后只有 **0.139**，
且两组范围**大量重叠**（B 的最好 0.845 > A 的最差 0.743）。**那个"不重叠"是单抽签的假象。**

**★ 判据不是"策略现在多强"**（这条反直觉但实测）：同为 eval 0.99 的两个 ckpt 给出 0.937 与
0.567；同为 eval 1.00 的给出 0.825 与 0.618。σ=0.02 与 σ=0.1 下的 eval 只差 0.02-0.07
（`scratchpad/eval_sig.py`），所以"按哪个 σ 口径算饱和"是伪问题。
起作用的是**训练轨迹有没有触顶**，不是策略的瞬时成功率 —— 与 §35「policy_only 不预测 adapt」同源。

### ③ ⛔ 全部作废的结论（按 0.092 的地板重算）
| 干预 | 曾报的 Δ | 现状 |
|---|---:|---|
| 采集噪声 | +0.134/+0.103/+0.007/−0.051（R²=0.947 剂量曲线） | ❌❌ **正式判死**：双侧各 5 seed 的预注册检验 **Δ=+0.017, SE=0.057, z=0.30**（配对差 −0.139~+0.138, 3/5）。此前 4 个版本依次是"4 配对中 3 个不配对"→"配对后无剂量关系"→"换正确基线 +0.321"→"多抽样 +0.080±0.091"，**五次翻转全部源于基线口径** |
| 噪声**强度**（¼×/½×/1×） | — | ❌ **非单调**（0.778/0.583/0.814），凹陷 0.23 = 抽签量级 |
| σ（初始分布） | N1 上 +0.247、N3 上 **−0.093** | ❌ 两次方向相反，全是单抽样 |
| demo 数 20→50→500 | +0.03/+0.05 | ❌ |
| stage-3 探索采集 `collect_disagree_coef` | +0.024 | ❌ |
| 池内筛选（matched/lenmatch/cfmax） | +0.15~+0.24 | ❌ 全是单抽样，且判据不跨池 |
| bc_steps 按 policy_only 选 | −0.060 (z=−5.26) | ⚠️ 配对 26 点，方向可信；但"该调 bc_steps"本身被否 |
| adapt 调度（interval/UTD） | −0.024 ~ −0.044 | ⚠️ 同上，结论是"别调" |

**筛选判据全灭（20+ 个）**：policy_only（两次给出**反向**结论，z=−5.3/−14）、demo 级
contact_frac（池内 ρ=+0.77 / 跨池 −0.03，刻意最大化反而更差）、长度、|Δa|、`cover_lat%`
（被噪声实验证伪）、**8 个闭环 MPPI 指标**（无一通过 Bonferroni p<0.0063；§35 记为"已验证"的
`contact_steps` 从 **ρ=+0.855 (n=10) 崩到 −0.209 (n=13)**，符号翻转）。
**⇒ 路线"采一大池再筛"目前没有任何可用判据**；且其理论上限（总能抽到最好的 ≈+0.17）
比换采集策略（+0.14~0.19）还低。

### ④ 采集口径的陷阱（今天踩了三个，每个都产生过错误结论）
1. **`collect_target_demos.py` 的 `--hole_offset`(默认 0.01) / `--solref_scale`(默认 0.8) 是
   无条件覆盖 ckpt 的 shift 的**（不像 `gripper_kp_scale` 那组 `default=None` 才覆盖）
   ⇒ 不显式传 `--hole_offset 0 --solref_scale 1.0 --solimp_scale 1.0` 就静默退回旧的带偏移
   target。25×2 条 demo 因此作废重采。
2. **`threading_d0_target_expert_n500` 是另一个脚本采的**（`collect_target_expert.py`，
   8 进程分片、`state_only_no_render`、按分片拼接 ⇒ "前 20 条"不对应 seed 1-20）。
   拿它当基线测出的"噪声 −0.051"是跨脚本比较，作废。
3. **`seed = args.seed + attempt`，一次拒收就让后续 seed 整体错位** ⇒ 两臂"同 seed"也可能
   落在不相交的初始状态上（实测 4 个噪声配对里 3 个是 0/20 或 3/20 重合）。
   **已修**：`write_dataset` 现在写 `demo.attrs["seed"]`，A/B 可按 seed 取交集。

### ⑤ 工具改动（都默认关、逐位兼容）
- `scripts/collect_target_demos.py`
  - **采集噪声**：`--noise_sigma_min/max`（默认 0 = 关）、`--noise_min/max`（噪声区间步数，
    默认 1-5）、`--nonoise_min/max`（干净区间，默认 5-10）。照搬
    `generate_simdist_data.py` 的**连续区间**方案（per-episode Σ=diag(σ)，σ_i~U[min,max]），
    **存执行后（加噪+clamp）的动作**作为 BC 目标。用连续区间而非逐步 iid：iid 会被 OSC
    控制器与下一个动作抵消，只污染 BC 目标、买不到覆盖（同 §27 oracle 注噪的
    iid-vs-smooth 结论）。已验证 `sigma_max<=0` 时与旧代码**逐位一致**（3 条 demo 全同）。
  - **`demo.attrs["seed"]`**：见 ④.3。
- `scripts/ablate_bc_steps.py`：`val_frac=0` 时不再 shuffle episode 顺序（否则 BC 采样序列
  与 `train_simdist_adapt.py::bc_finetune` 不一致，选出的步数不转移）。

### ⑥ 准则（给真机 demo 采集）
1. **用"已经胜任、但表现还在提升、尚未触到天花板"的演示者/策略采集。** 一旦它开始百发百中，
   数据价值掉 **0.14–0.19**。判据是**成功率还在不在涨**（session-over-session），
   **不是**"他现在多准"（后者实测不预测 adapt）。
2. **采 50-100 条，不是 20 条。** 主要目的**不是提高均值**（20→50 只值 +0.03），而是压掉
   ±0.09-0.11 的抽签方差 —— 可控效应只有 0.14，不压方差根本看不见。
3. **不要筛 demo**（20+ 判据全灭），**不要调 SimDist 超参**（bc_steps/adapt_interval/UTD
   三个方向全部 ≤ 基线，总跨度 0.044）。
4. **做 A/B 比较：同脚本、同 seed 起点、每条件 ≥5 次独立采集比均值。**

### ⑦ 方法论（本节真正的产出）
- **先量噪声地板，再测效应。** 我跑了 20+ 个实验才回头量抽签方差，导致大半结论作废。
  代价：4 次采集 + 4 个 adapt 就能提前拿到这个数。
- **事后发现的规则必须预注册复现。** 今天两条事后规则：「eval∈[0.95,1.00) 窗口」预注册后
  **死**（预测 ≥0.90，实测 0.847）；「是否触顶」预注册后**缩水 2.4 倍**（0.337→0.139）。
- **判据必须是最终目标**，中间代理会给反向结论（`policy_only` 两次，z=−5.3 / −14）。
- **中途窗口会翻符号**（18k 领先 +0.029 → 满窗落后 −0.224）。
- **同一个结论在本节翻转过四次**（噪声：+0.13 → 无剂量关系 → +0.32 → +0.08 不显著），
  **每次都源于基线的采集口径，没有一次来自新数据。**
